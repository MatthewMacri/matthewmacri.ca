I started at Tokidos in customer support in late 2024 and moved through three internships into a
full-time developer role. Over that time I built and now maintain a handful of small production systems
that run on one AWS server, kept deliberately lean with scheduled jobs rather than extra infrastructure.
The code and data are private, so this is a description of what they do, not a tour.

## Internal tools (summer 2025)

Customer and order data lived in several places: Shopify for orders, a subscription service for
renewals, a fulfilment provider for shipping. Answering "where is this customer's box?" meant opening all
of them.

I built a PHP dashboard that pulls from those APIs into a database on a schedule and shows one view per
customer, plus two smaller tools on top of it:

- **KPI dashboard**: the numbers the team tracks, on one page that also works on a phone.
- **Support dashboard**: groups incoming errors by pattern, so a problem that hits many customers shows
  up as one row instead of many separate tickets.

Over time this grew into a set of internal admin tools the operations team uses day to day.

## A data pipeline for the store (2025–26)

Business questions like "what's our average order value?" used to mean exporting from Shopify by hand and
working in a spreadsheet. I built a pipeline that syncs Shopify orders, customers and products into a
database in near real time, so those questions become a SQL query that runs in seconds. It's also the
backbone the recommendation engine relies on for attribution.

## A recommendation engine (2026)

Marketing emails were generic blasts. I built an engine that suggests the right next game to each
household based on what their child actually plays:

- **Behaviour-based triggers.** More than thirty rules (for example, "played a game several times in the
  last month") decide who is a good fit for which recommendation, in priority order, with a cap so nobody
  is emailed too often.
- **Bilingual, templated emails.** It sends through Klaviyo in English or French, picked from the
  household's settings, across a branched flow of templates.
- **Full attribution.** It tracks the whole funnel — send, open, click, purchase, refund — by matching
  against the Shopify pipeline, so its effect can actually be measured rather than guessed at.
- **Autonomous.** It runs on a daily schedule with no manual step.

The honest next step is a proper holdout test — a slice of eligible households that gets no email — so the
engine's real lift can be separated from sales that would have happened anyway. That's what turns "looks
promising" into a number worth standing behind.

## Keeping subscriptions clean (2026)

A bug in the subscription integration could charge and ship the same renewal twice. I built a check that
runs before renewals go out, catches duplicates and logs them, so customers aren't double-billed and the
team isn't left processing refunds and returns.

## Data analytics (fall 2025)

Gameplay and voice metrics: which activities users came back to and where sessions dropped off. I built
the dashboards for that, checked data quality, and tested the recommendation system against what people
actually played.

## The app (2026)

The current app is a WebView wrapped in a native shell. That made shipping easy but means slow loads,
awkward auth and behaviour that differs between devices. I'm rewriting it in Flutter as a fully native
app, starting with authentication and the screens people use most.
